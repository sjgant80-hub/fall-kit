One brain for every build. Yours to switch on.

Fall Kit is one small script. Put it in a web page and that page gets an AI helper that the person using it controls: off, a model that runs inside their own browser, or their own key to a frontier model such as Claude. Nothing goes through us: there is no server, no account and no middleman.

It is also the first of five studs on the Lego socket, the standard every estate build carries so that any build fits any other.

If you are using an estate build

  1. Find the small AI chip on the page (on this page it sits in the header, top right).
  2. Click it. Pick Off (the build works without AI), In your browser (a model downloads once and runs on your own machine), or Your own key.
  3. For your own key: choose the provider, paste the key, close the panel. The key stays in this tab and is gone when you close it, unless you tick remember my keys on this device.
  4. Ask: the top of the same panel has Ask about this page. Type a question about the build you are on, such as "how do I use this?", and the brain you picked answers from the page's own words.
  5. Use the build as normal. Wherever it offers AI help of its own, that help comes from the same brain.

If you are building one

  1. Add one line before </body>: <script src="https://sjgant80-hub.github.io/fall-kit/shim.js" defer></script>. Or copy the kit into the page with node porter.mjs <your-build> so it works offline.

  3. Write the build's kard.json with node kard-writer.mjs <your-build> … so the build fits the socket.

How it works

Your page asks a question. Fall Kit sends it to whichever brain the person picked, and hands back the words of the answer, or null.

  1. The page asks. It passes an opening (who the helper is and what it knows), the conversation so far, and the new question.
  2. Off: the kit answers null at once. No download, no call. Every estate build must still work this way.
  3. In your browser: the kit loads WebLLM the first time you choose it, then the model answers on your own graphics chip. Nothing is sent anywhere.
  4. Your own key: the kit builds the provider's request itself (below is the real one), sends it from your browser straight to the provider, and reads back only the words of the answer, never the model's private thinking.
  5. The receipt: FallKit.lastUsage() then says how many tokens the provider read, how many it recycled from its cache, and how many it wrote.

Recycling: the opening is paid for once

Every question in a talk sends the same opening before the new words. Fall Kit puts that opening first, keeps it the same every time, and marks it for the provider's cache. The provider then stores it once and reads it back for every later question at a fraction of the price. On Claude Opus 5.5 a cache read costs $0.20 per million tokens instead of $4; writing it costs $5 per million, once. OpenAI, Google and OpenRouter recycle repeated openings on their own.

Two conditions, stated straight: the opening must be at least 512 tokens on the newest Claude models, and the next question must start within five minutes (each read restarts the five minutes). Prices: Anthropic's published Claude API rates for Claude Opus 5.5.

What it costs your team, worked out by recycle.mjs

Answers include the model's thinking, which is billed as output. Only the opening is counted as recycled; a real talk also re-reads its earlier turns from the cache, so the true saving is larger.

Your keys stay in the tab

Every estate page lives at the same web address, sjgant80-hub.github.io, and browsers give pages at one address one shared storage. A key kept there could be read by any of them. So from version 3:

  • A key you paste is held in this tab's memory only. Close the tab and it is gone.
  • If you want it kept, tick remember my keys on this device. The panel tells you what that means first.
  • Forget my keys clears every key at once, kept or not.
  • A key saved by an older version is moved out of shared storage the first time version 3 loads. You will see a note saying so, and you paste it once more.
  • The Google key travels in a request header, not in the web address, so it does not show up in logs.

The Lego socket

A Lego brick fits any other because every brick has the same studs in the same places. The socket is that idea for software: five things every estate build carries, measured from the build's own files and written down in one small file, kard.json. Anything built now or later can read that file and know how to fit.

StudWhat it meansHow it is measured
brainFall Kit is in the build, so it has the AI helper: at the least, you can ask it about the page you are on.Fall Kit's markers in the page (and which version), its one-line loader, or a linked copy of fall-kit.js
manifestThe build says who it is, what rented tool it retires and where it lives.its kard.json, checked field by field
meshBuilds open on the same device can talk; some talk across devices too.Fall Kit's same-device channel or the build's own; the build's own WebRTC for across devices
memoryThe build keeps your work on your own device.IndexedDB or local storage in the build's own code (the kit keeping its settings does not count)
proofThe build is tested on GitHub's machines, not just on ours.its workflows, and its test files

A build fits when it has every stud. One that does not still has a card; the card simply names the stud it lacks. Kardlings reads these files to make its gear cards.

Embed in your build

Two ways. Copy it in for a build that works offline: node porter.mjs <build-dir> puts fall-kit.js into the page between its markers. Or load it with one line, which always gets the newest version.

<script src="https://sjgant80-hub.github.io/fall-kit/fall-kit.js"></script>
<script>
  FallKit.init({ seedName: 'my-build', chipAnchor: 'header nav' });

  // one question · null when AI is off, so the build does its own thing
  const draft = await FallKit.aiComplete('You are a tight technical writer.', 'Summarise: ' + text, 200);

  // a conversation that recycles its opening · the history only grows, never edited
  const r = await FallKit.aiChat(OPENING, history, question, 600);
  if (r) { history.push({ role: 'user', content: question }, r.assistant); show(r.text); }
  console.log(FallKit.lastUsage());   // { read, recycled, written, out }
</script>

For a business

Put an AI helper in every tool your people already use, without a new vendor, a new seat licence or a server, and pay the AI provider only for the words actually sent.

What it does for each role

RoleWhat changes
CEOAI help inside every internal tool, under your own control, in weeks rather than a procurement cycle. No new company sits between you and the model.
CFONo licence fee: the kit is MIT. You pay your chosen provider at its published rates for what is used, and recycling cuts the repeated part. The calculator above works out the month for your numbers.
COOThe same chip and the same settings in every tool, so people learn it once. Tools keep working when AI is off.

Security, data protection and compliance

  • Where data goes: Off sends nothing. In your browser sends nothing. Your own key sends the question to that provider only, under your agreement with that provider. Fall Kit adds no processor of its own: it has no server, no analytics and no account.
  • Keys: held in tab memory; kept on the device only when the person ticks the box; cleared with one button.
  • Locking it down: set a content security policy on your pages that allows only your approved providers. Kardlings, an estate build, does exactly this for four providers.

Rolling it out

  1. Week 1: add the kit to one tool. It starts Off, so nothing changes for anyone.
  2. Week 2: a pilot team turns on In your browser, where the data must stay on the machine, and Your own key with the company's provider.
  3. Week 3 on: add it to the next tool with porter.mjs; write each tool's kard.json so it fits the socket.

Support and ownership

MIT licence: copy the kit into your own tools and it is yours, with no lock-in and nothing to renew. Questions and fixes go through the GitHub repository.

Risks, answered straight

  • A key in a browser tab can be read by any script running on that page. Put keys only into pages you trust, set a content security policy, and close the tab when done. The key does not outlive it unless kept on purpose.
  • In-browser models need a recent browser with WebGPU and room for the model. On older machines, Off and Your own key still work.
  • Providers change models and prices. The model lists live in one file; the calculator takes the rates as inputs.
  • Recycling needs a long enough opening and questions within five minutes. Below that, you pay the normal price and nothing breaks.

The case for the board

AI in every tool, owned outright, no per-seat licence, no new data processor, and a provider bill that falls as people use it more, because the repeated part is recycled. The source is open, and the tests run where anyone can see them.

Doctrine

  • Off must always work. The kit never hides a build's core feature behind AI.
  • Keys are never proxied. They go straight from the browser to the provider, held in the tab unless the person keeps them.
  • Models download only when asked. The kit itself is one file.
  • One channel name. Builds on the same device meet on fall-signal (a BroadcastChannel; it does not cross devices).
