Phase 3 of the estate going live · thirteen claims sealed before the code

Many nodes, one mesh, and nothing in the middle you have to trust

The foundation's nodes now run together as a mesh. Each node is its own program. They find each other through small relays that carry bytes and read nothing else. Work goes to the node whose answers check, and a node or relay that dies is routed around. A shared map stays the same everywhere, and when one node learns to refuse an attack, the whole mesh soon recognises it.

Every message is a LIGHT packet its sender signed. The node it is for checks it at its own door before reading a byte of it. So the relays, the network and every other node can be wrong, or hostile, and the worst they can do is fail to deliver.

Start here

If you want to see it work

  1. Start the mesh below. Six real foundation nodes start in your tab: two honest triage holders, one dishonest one, a scribe, and two askers. The founder signs a roster of them, and each node pins every member on it.
  2. Ask for triage a few times. Each ask goes to a holder of the skill, and each asker tries every holder once before it settles (the table marks the ones it has not tried). The answer's receipt is checked, and the asker's link to that holder grows if it checks and falls if it does not. When it does not, the asker keeps the dishonest holder's own signed answer as evidence and shares it; the other asker checks it for itself and counts it too.
  3. Kill relay A, then ask again. Everything goes through relay B. Now kill the holder the asks are going to (the log says which) and ask: the first ask to it is not answered, expires and counts as a failure, and that asker tells the others. They mark it quiet at once and send it a probe; when nothing answers, their links fall too, so their next asks go elsewhere without losing one. Bring it back: the relay hands it what it held while it was away, it answers the probes, and the others count it live again; its link has to be earned back.
  4. Write and sync. Write a key at one node, then sync. Every live node ends with the same map: the short code under each node is its map's fingerprint.
  5. Attack it. Have the stranger forge a packet at a1, then share what a1 learned, then send the same bytes to everyone. Every node now recognises them on sight. Try a variant.
  6. Drop a member. Have the founder sign a roster without the dishonest holder. Every node unpins it, and what it sends next stops at the sender.
  7. Read the receipt: the measured claims, re-judged in your tab from the receipt's own facts.

    How it works

    1. Joining. The founder signs a roster: the card of every member. Each node reads it, checks the founder's signature and every card, and pins the members' keys. A card not on the roster is not pinned, however well it is signed. Pinning is the only way a node trusts anyone.
    2. Carrying. A node says hello to every relay it knows. To say something, it wraps a signed packet in a frame naming the recipient and hands it to the first relay that is up. The relay delivers it, or holds it for a node that is away and delivers it when that node says hello again.
    3. Routing. To ask for a skill, a node picks the holder its links rate highest. When an answer comes back, its receipt is re-checked. The link grows if it checks and falls if it does not. An ask nobody answers expires and counts as a failed answer, so a node that died is routed around.
    4. Sharing state. Each node keeps a copy of a shared map. A write is stamped with the writer's Lamport time and id. A sync carries a node's whole map as a signed packet, and the receiver merges it entry by entry: the later stamp wins, and the node id breaks a tie. Whatever order syncs arrive in, every copy ends the same. The kernel is fallsync's, gated in its own repository first, copied byte for byte.
    5. Sharing immunity. Every packet a door refuses becomes an antibody. A node can share its antibodies as a signed bundle. The receiver re-runs each one on its own door and adopts only those its own door also refuses, so one node's mistake cannot teach the others to refuse their own peers.
    6. One packet at a time. A node hears one packet at a time, in order. Found while going live: two packets heard at the same moment could both read a sender's old counter, and the lower could set it back, letting the higher be replayed. Hearing is now a queue, and a test holds it there.

    The fix for J3 and J4, measured: Phase 3b

    Phase 3's two failures had one cause: every asker routed on its own evidence and took the best it knew. Phase 3b changes the routing in four small ways. Four new claims were sealed before any of its code existed, and they were measured on Phase 3's own scenario, with Phase 3's routing run beside it on the same seeds as the control.

    What changed, in plain words

    1. Askers keep notes, and share them. When an asker's ask goes unanswered, it notes that the holder went silent. When a holder answers with a receipt that does not check, the asker keeps that holder's own signed answer as evidence. It sends its notes to the other members as one signed message, the way nodes already share antibodies.
    2. Nobody acts on someone else's word. A note of a lie counts only if the packet in it really is the accused holder's own signed answer to that asker, for that ask, and the receiver's own check fails it too. A note of silence makes the holder "quiet" at the receiver at once, so its asks go elsewhere, and the receiver sends the holder a small probe of its own. If the holder answers, it is alive and nothing changes. Only a probe that goes unanswered counts as a failure.
    3. A quiet holder is live again the moment it speaks. Any signed packet from it that the door admits clears it, so a node that comes back and answers the probes the relays held for it is live again at every node that probed it. Its link stays where the silence left it until its answers earn it back.
    4. Every holder is tried once. An asker asks a holder it has never asked before one it has, then the strongest link, then the smaller key. So a dishonest holder that ranks last is still asked, once by each asker, and caught.

    W4, the claim: a note moves nothing on its sender's word.     What it costs, and how close it came

    • One ask per holder, per asker. Each asker spends its first asks of a skill trying every holder once. In this run that was four asks to the dishonest holder in all, one from each asker, all within the first 20 asks, and none after. The cost grows with the number of holders of a skill: with ten holders, an asker's first ten asks of it go one to each. Each of those answers is checked like any other, so a lie from an untried holder is caught, not used; what exploring costs is time. A holder the mesh has already proven a liar, pushed under the floor by others' evidence, is not explored at all.
    • One probe per member, per silence. When an asker reports a silence, every other member sends the silent holder one small signed probe, and no second one while that holder stays quiet. Nobody's work waits on it.
    • One message per member, per new note. In a mesh of N members a new note costs N−1 signed messages, one to each other member. A note of a lie carries the liar's answer packet, a few hundred bytes here.
    • The margin on the floor. A fresh link is 50%. Each failure halves it: four take it to 3.1%, under the 5% floor; three leave it at 6.25%, over it. This mesh has four askers, each finding the liar once and counting the other three's evidence, so it crossed the floor exactly. That was predicted before the run and written into the claims. With fewer askers, a mesh needs more evidence per asker to cross it.

      Security and data protection, answered straight

      • What it stops. A message from a key not on the founder's roster, at the sender. A forged one, at the signature. One changed in transit, at the signature or earlier. One sent twice, at the counter. One meant for another node, before it is acted on. Junk, at the first bytes. The receipt sends all of these, from sixteen hostile nodes, and none is admitted.
      • What it does not stop. A member whose key is stolen, or whose machine is compromised: it signs what it likes, and the mesh trusts it until the founder signs a roster without it and each node reads that roster. Each node then unpins it, keeping its last counter so nothing it sent before can be replayed. Dropping a member is built, tested and mutation-gated (core/node.mjs unpin, core/roster.mjs rosterChanges), and runs in the tab above; it is not one of Phase 3's sealed claims. A member that answers badly is not stopped either, only routed away from once its answers fail to check. Under Phase 3's routing a liar that was never asked was never found out (J4); Phase 3b's routing asks every holder once, so it is found, and the evidence of it is shared (W2, W3). A relay that drops everything denies service.
      • Where data goes. Only to the node a message names, through relays you run. A relay sees who a frame is for and how long it is, never what is in it. Nothing here calls any outside service.
      • Personal data. A relay holds no app data, only a short queue of frames for nodes that are away, which expires. Each node keeps its own copy of the shared map, so personal data in it lives on every member you put on the roster: put on it only the nodes that may hold it (UK GDPR and GDPR).

      Rolling it out

      1. Two services, one relay. Put a node in front of two systems that already talk to each other, run one relay beside them, and sign a roster of the two.
      2. A second relay, on another machine, so that losing one costs nothing.
      3. Then the next service, one at a time, each added to the roster, with what it shares in the shared map declared first.

      Risks, answered

      • "It was measured on one machine." Yes. Every node and relay was its own process, talking only over TCP, which is how they would talk across machines; but a second device and a real network are not on the receipt.       • "Last writer wins loses edits." When two people change the same key at once, one change wins and the other is kept nowhere. That is the rule, stated in the claims, and it is right for status and settings. A document two people edit together needs a different merge.
      • "A liar can hide." Under Phase 3's routing it could: J4 showed a dishonest holder that was never asked was never caught.       • "How fast is it?" Not on this receipt. Every scenario runs one step at a time so that its receipt is the same on every machine, which is the opposite of a load test. Throughput under load is a measurement of its own.
      • "A dead node costs one ask per asker." It did under Phase 3's routing (J3). With Phase 3b's, the first asker's unanswered ask warns the rest, so the mesh loses one ask in all (W1). Each other member sends the dead node one probe, a small signed packet; nobody waits on it.
      • "Exploring sends real work to a holder nobody has tried." It does, once per asker per holder. The answer is checked before it is used, as every answer is, so an untried liar costs one ask and is caught (W3). What it can cost is time, if the untried holder is slow: that is the price of finding out, paid once.
      • "A false report of silence could hurt an honest holder that is slow." It can, by one failure. A false silence makes the holder quiet at each receiver only until it answers their probe, which a live holder does at once. If it is so slow that a receiver gives the probe up first, that receiver counts one failure, as it would for any ask that went unanswered. It cannot make the holder quiet for good: the first packet from it clears it.
      • "A member could spread false reports about the others." It can send them, and they move nothing: a report of a lie counts only on the accused's own signed answer failing the receiver's own check, and a report of silence only when the receiver's own probe goes unanswered.       The case for the board

      The organisation's systems can depend on each other without depending on a middleman. Trust is one signed list. Failures are routed around instead of escalated. Every claim behind that is re-run by a machine anyone can watch, including the one that failed.

      The paper: a mesh with nothing to trust in the middle

      The problem. Systems that talk to each other usually talk through something in the middle: a broker, a gateway, a service mesh's control plane, a cloud queue. That middle sees every message, and it has to be up, so it becomes the thing to defend and the thing that fails. The usual answer is to make the middle stronger.

      The design. Make the middle unable to matter. Relays carry frames and read nothing but the recipient's id; their code imports no codec at all. Every body is a LIGHT packet its sender signed, checked by the recipient's own door, so trust lives at the edges, in the founder's roster and each node's pins. Routing is by evidence: each node keeps links to its peers that grow when answers check and fall when they do not or never come. Shared state is a CRDT, so it converges without a coordinator. Immunity is shared, but adopted only after each node re-checks it on its own door.

      What is measured. Thirteen claims were committed before any of Phase 3's code, across five passes. The relay fabric: every frame reaches the node it names, no body is decoded, a relay can die, a node that is away gets what was held for it, once. Joining and routing: the roster, routing by skill and by answers that check, routing around a dead node, and links that follow evidence. Shared state: convergence in three shuffled orders with a relay killed, and nothing changed by a stranger or a forgery. Shared immunity: one node's lesson recognised by all, a crowd of sixteen hostile nodes, and the mesh still working afterwards. Browsers: two tabs over WebRTC. Every node and relay runs as its own process, the run goes one step at a time on fixed public test seeds and a fixed clock, and CI re-runs it and demands the same receipt byte for byte.

      What it found. Two claims failed and are kept, both from one fact: each asker routes greedily on its own evidence. When the node being asked dies, every asker finds out separately (J3). A liar that routing never asks is never caught (J4). Going live also found a real bug before any claim was judged: two packets heard at the same moment could set a sender's counter back and let a replay in. Hearing is now one packet at a time, with a test that holds it. It found a fault in its own measuring: the first build of the J3 run killed a holder no ask was going to, which could not fail. It was corrected before the receipt was kept. And X1 found that falllink, the estate's connection layer, had never completed a same-device connection in Chromium; that was fixed in falllink, under a mutation gate, before X1 was measured.

      Phase 3b: the fix, measured. The cause of J3 and J4 was one design choice, so the fix is one organ: routing that shares what it learns. Askers keep notes of what they saw themselves (a silence, or a lie with the liar's own signed answer) and share them as antibodies are shared; nothing is acted on until the receiver's own check agrees (its own reading of the liar's signature and receipt, or its own unanswered probe); and every asker tries every holder once. Four claims were sealed before the code and measured on Phase 3's scenario, with Phase 3's routing run beside it as the control. The dead node got 1 ask instead of 4; the dishonest holder was asked once by each asker and its link fell to 3.1% everywhere, against 50% before; and false notes from a pinned member moved nothing. One claim failed on its own wording: four false notes were answered as already judged rather than refused, because they repeated bytes the receiver had judged a moment before. Phase 3c fixed that as a sealed claim of its own: a note is now judged against the holder it names before it is checked as a repeat, all 16 were refused by name, and W1 to W3, re-measured, came out digest for digest as before.

      Honest limits. One machine, and two tabs of one browser. Hostile nodes that send what the door is built to refuse, not an outside red team. Last writer wins, not a merge of concurrent edits. A stolen member key is trusted until the founder signs a roster without it and the nodes read it. Throughput under load is not measured.

      Questions

      What is a relay, and can it read my data?

      A relay is a small process that carries frames to the node each frame names, and holds them a while for a node that is away. It reads the recipient's id and nothing else. Every body is a LIGHT packet the sending node signed, and the receiving node's own door checks it, so a relay that lies, drops or replays costs delivery, never safety. The relay's law (core/relay.mjs) imports nothing at all, no codec, door or vault, and the process around it (core/relay-server.mjs) only moves bytes over TCP; the receipt checks the first.

      What happens when a node or a relay dies?

      Every node says hello to every relay, so when a relay dies the nodes go on through another: in the measured run relay A was killed halfway and all 50 later asks were answered through relay B, with every node's state the same as a run where nothing died. When a node dies, its unanswered asks expire and count as failed answers. Under Phase 3's routing each asker lost one ask to it first (J3, failed and kept). With Phase 3b's routing the first asker that finds out tells the others, who mark the node quiet at once and check with a probe of their own, so the mesh loses one ask in all (W1).

      How is shared state kept the same?

      Each node keeps a copy of a shared map, a last-writer-wins CRDT by Lamport time with the node id as the tie-break, gated in fallsync first. Changes travel as signed LIGHT packets; only a pinned member's sync is merged. In the measured run eight nodes ended with the same map in three different shuffled orders, one of them with a relay killed halfway.

      What is shared immunity?

      When a node's door refuses a packet it remembers it as an antibody. It can share its antibodies with the mesh, and each node adopts one only after re-running it on its own door. In the measured run one forged packet refused at one node was, after one round of sharing, recognised on sight by all eight, without decoding.

      What did not hold?

      In Phase 3, two claims failed and are kept. J3: when the holder the asks were going to died, each of the four askers sent one ask to it before moving on, four against a bar of two. J4: the dishonest triage holder was never asked, so its link never fell. Phase 3b fixed both, measured on the same run (1 ask instead of 4; the dishonest link at 3.1% instead of 50%), and one of its own four claims failed: W4, where four false notes were answered as already judged instead of being refused. None of them moved a link. Phase 3c then fixed W4 as its own sealed claim: all 16 are now refused by name, and nothing else the routing measured changed.
